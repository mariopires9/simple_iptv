# UX-03 — Keyboard navigation and accessibility audit

**Status:** In review (2026-10-30) · agent `implementer` (worktree, branch `story/UX-03`)

## Delivered
- **Skip link (AC3):** `src/app/shell/SkipLink.tsx` — "Skip to content" / "Saltar para o conteúdo" (`nav.skipToContent`, en + pt-PT). It is the first focusable element of the AppShell and of the full-screen (onboarding) layout, off screen until it has focus, and moves focus to `<main id="main-content" tabindex="-1">` with a click handler (the hash router owns the URL hash, so there is no `#id` navigation). `src/app/AppShell.tsx` only gains the link and the landmark props.
- **Defect fixed — focus lost after closing the live player:** Esc or "Close player" left focus on the removed player (the document body), so the next Tab started from the top of the page. `LiveScreen` now returns focus to the channel list (`#live-channel-list`) once the player is gone. Movie and episode players already returned focus to their Play button.
- **Keyboard E2E (AC1):** `e2e/keyboard.spec.ts` — skip link → onboarding Xtream form (synthetic panel) → Live (Tab to the listbox, Home, Enter) → ↓ zaps → Esc closes, focus back on the list → Movies (grid tab stop, Home/→ roving focus, Enter) → Play, Esc, focus back on Play → `/` → type → ↓ to the result → Enter plays the channel. Only Tab/arrows/Enter/Esc/typing; WebKit uses Alt+Tab (Safari skips links on Tab). Runs on the desktop projects; skipped on the mobile ones.
- **axe (AC2):** `e2e/a11y.spec.ts` now also covers `/settings/sources/diagnostics` (after the checks finish) and `/settings` with a saved personal proxy (Remove button and enabled routing selects). The other routes were already covered by QA-02.

## Audit notes (no defect found)
- Channel list: one tab stop, `aria-activedescendant`, ↑/↓/PageUp/PageDown/Home/End, Enter plays, F toggles favorite.
- Poster grids: roving tabindex, arrows/Home/End/PageUp/PageDown, Enter opens.
- Player: focus moves to the player region on open; Esc closes (leaves fullscreen first); "Channels" panel closes with Esc and returns focus to the player.
- Search: `/` opens it with focus in the field; ↓/↑ move through the results.
- Menus and dialogs are MUI (focus trap, Esc, focus restore).

## Manual checklist for AC4 (owner, DEP-02)
Use the synthetic panel or your own authorized list. Record the browser, OS, screen reader and version in `docs/progress/compatibility-matrix.md`.

Screen readers: NVDA + Firefox and NVDA + Chrome (Windows); VoiceOver + Safari (macOS); VoiceOver + Safari (iOS, swipe navigation).

1. Load the app and press Tab: "Skip to content, link" is announced first; activating it moves to the main content.
2. Go to Live: the channel list is announced as a list box named "Channels in <category>", with its usage hint (arrow keys, Enter, F) and "<channel>, n of N".
3. ↓/↑ in the list: each channel name (and "Favorite" for favorites) is announced with its position.
4. Enter on a channel: "Watching <channel>" is announced (polite) and focus is in "Player: <channel>".
5. ↓ / ↑ in the player (zapping): every new channel is announced once as "Watching <channel>", without the previous one being read again; holding the key does not flood announcements.
6. Tab through the player controls: every button has a name (Play/Pause, Mute, Previous/Next channel, Channels, Fullscreen, Close player) and its state where it has one.
7. L opens the "Channels" panel; Esc closes it and focus returns to the player.
8. Esc closes the player; focus returns to the channel list and the selected channel is announced.
9. A channel that fails to play: the error message and its actions (Try again, Next channel) are announced.
10. Switch the language to Português and repeat 4–5: announcements are in Portuguese with Portuguese pronunciation (`<html lang="pt-PT">`).

Result: note per step pass/fail and the exact announcement for any failure.
