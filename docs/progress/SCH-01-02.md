# SCH-01/02 — Search index and global search

**Status:** Done (2026-10-29) · agent `media-engineer` (worktree) · review: `/code-review`

## Delivered
- Worker search index (`src/worker/search`) with `minisearch@7.2.0` (MIT, data-worker chunk only): names + channel numbers, prefix on every term, one typo for terms ≥ 5 letters, diacritics ignored, all terms must match. No URLs, logos or credentials in the index; logs carry ids, counts and timings only.
- Stored per source; every catalogue write deletes that source's index in the same transaction (`onCatalogWrite` drops the worker's in-memory copy), so freshness does not depend on clocks. Rebuilt after each sync that wrote data, queued per source after the sync finishes (the sync never waits for it); a query waits for a pending build.
- Global search (`/search`): `/` shortcut and top-bar icon, 120 ms debounce with abort, results grouped by type (20 each + "See all" up to 200), result links into Live/Movies/Series, last 10 searches (serialized read-modify-write), empty/no-list/error states, search landmark and live result count.
- Shared query rule in `@/core/db` (`isSearchableQuery`, `tokenizeSearchText`, `MIN_SEARCH_QUERY_LENGTH`); `catalogRepo.getCategories` bulk read. New lazy i18n namespace `search`.
